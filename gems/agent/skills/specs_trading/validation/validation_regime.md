# Regime Analysis（市場狀態分析）

## 目的

確認策略在**不同市場狀態**下都能獲利，而不是只在特定行情下有效。

一個策略如果只在牛市有效，遇到熊市或震盪就大幅虧損，實盤風險很高。

---

## 核心概念

把回測時間按季度切分，每季代表不同的市場狀態：

```
2025 Q1（1~3月）：牛市高位 → 策略在高位能否正確判斷方向？
2025 Q2（4~6月）：熊市下跌 → 策略在下跌中能否做空獲利？
2025 Q3（7~9月）：震盪反彈 → 策略在震盪中是否雜訊太多？
2025 Q4（10~12月）：趨勢恢復 → 策略在趨勢行情中表現如何？
```

---

## 執行方式

```bash
node backtests/tests/validation/bt_validate_universal.js BTCUSDT
node backtests/tests/validation/bt_regime_analysis.js
```

## 輸出範例

```
【Regime Analysis】
  市場狀態       筆數   勝率      損益      每單
  牛市(Q1)      15  53.3%   -1.99U  -0.13U  ⚠️
  熊市(Q2)      22  81.8%  +31.62U  +1.44U  ✅
  震盪(Q3)      18  83.3%  +20.25U  +1.12U  ✅
  趨勢(Q4)      19  73.7%  +24.83U  +1.31U  ✅
```

---

## 通過標準

- ≥ 3/4 季獲利
- 虧損季的損失不超過其他季獲利的 50%

## 解讀指引

**某季虧損不一定是問題：**
- Q1 牛市高位虧損 → 可能是高位震盪，訊號品質差，屬正常
- Q2 熊市虧損 → 策略可能偏多頭，需要加強空頭邏輯
- Q3 震盪虧損 → 策略在橫盤市場雜訊多，可考慮加 ADX 過濾

**需要重新審視的情況：**
- 連續 2 季以上虧損
- 某季虧損超過全年獲利的 30%
- 勝率在某季跌破 30%

---

## 注意事項

- 季度切割是固定的，不代表市場狀態一定如描述
- 每季至少需要 5 筆交易才有參考價值
- 通用工具（bt_validate_universal.js）目前整合在 Walk-Forward 中，Regime 分析需用獨立腳本
