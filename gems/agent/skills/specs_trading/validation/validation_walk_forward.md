# Walk-Forward Validation（滾動驗證）

## 目的

驗證策略參數在**樣本外資料**的穩定性，防止過擬合。

如果策略只在訓練資料上表現好，在新資料上表現差，代表過擬合。Walk-Forward 把資料切成多段，模擬真實的時間序列特性。

---

## 核心概念

```
資料時間軸：
  ├── 段1 ──┤ 段2 ──┤ 段3 ──┤ 段4 ──┤ 段5 ──┤
  
  驗證方式：每段都當一次「樣本外」驗證集
  通過條件：≥ 70% 的段落獲利
```

---

## 執行方式

```bash
# 通用工具（自動切段）
node backtests/tests/validation/bt_validate_universal.js BTCUSDT

# 獨立腳本
node backtests/tests/validation/bt_walk_forward.js
```

---

## 段落設計

通用工具會根據資料長度自動切段（每段約 3 個月）。以 15 個月資料為例：

| 段落 | 時間範圍 | 說明 |
|------|---------|------|
| 段1 | 2025 Q1 | 牛市高位 |
| 段2 | 2025 Q2 | 熊市下跌 |
| 段3 | 2025 Q3 | 震盪反彈 |
| 段4 | 2025 Q4 | 趨勢恢復 |
| 段5 | 2026 Q1 | 樣本外驗證 |

---

---

## 通過標準

- ≥ 70% 段落獲利（5段中至少4段）
- 各段勝率不低於 40%
- 最後一段（最新資料）獲利尤其重要

## 警告信號

- 某段 OOS 大幅虧損 → 該時期市場狀態特殊，策略不適應
- 前幾段好、後幾段差 → 策略可能在市場結構改變後失效
- 每段訊號數 < 5 → 樣本太少，結果不可靠

---

## 注意事項

- 通用工具的段落切割是等時間長度，不是等訊號數
- 某段訊號數為 0 代表該時期市場條件不符合策略，不算失敗
- 建議資料至少 6 個月才有足夠的段落數
